### 初始 VPS 密码怎么处理

脚本**不读取、不保存、不写文件**。

第一次 SSH 时由 Windows OpenSSH 自己询问：

```text
user@host's password:
```

你正常输入即可；终端不显示字符是正常行为。

### SSH key 怎么处理

启动器自动为这个：

```text
host + SSH user
```

生成独立 Ed25519 keypair，保存在：

```text
%USERPROFILE%\.ssh\proxy-runbook\<host>-<user>\
```

生成后屏幕会全文显示：

```text
REAL SSH PRIVATE KEY
REAL SSH PUBLIC KEY
```

然后：

```text
只把 Public Key 写入 VPS authorized_keys
→ BatchMode 真验证 key 登录
→ 验证通过后才上传工具包
```

**VPS SSH host private key 不导出。** 启动器和远端只展示 host public-key fingerprint。

### 上传/初始化

key 登录验证成功后自动：

```text
scp → /tmp/proxy-runbook-toolkit-v0.6.tar.gz
sudo/root 解包 → /opt/proxy-runbook-v0.6
建立 /opt/proxy-runbook-current
安装 proxy-node 维护命令
启动自适应 FRESH / EXISTING 向导
```

# 4. 全新 VPS：施工前先验尸

## 4.1 Windows：在你平时真正会出问题的网络下测

最好用你平时的手机热点/移动网络。

把 `<VPS_IP>` 换成新 IP：

```powershell
ping <VPS_IP>
```

然后：

```powershell
Test-NetConnection <VPS_IP> -Port 22
```

再：

```powershell
Test-NetConnection <VPS_IP> -Port 443
```

解释：

- 22 成功：至少 SSH 路径通。
- 443 此时如果服务器没人监听，失败不代表 IP 坏。
- 如果 22 明明有 sshd 监听，但你的常用网络始终到不了，**先查 IP/线路，别先装一堆东西**。

## 4.2 SSH 登录

```powershell
ssh root@<VPS_IP>
```

如果 SSH 不是 22：

```powershell
ssh -p <SSH_PORT> root@<VPS_IP>
```

第一次问：

```text
Are you sure you want to continue connecting...
```

输入：

```text
yes
```

看到：

```text
root@xxxx:~#
```

继续。

## 4.3 VPS 只读体检

```bash
cd /opt/proxy-runbook-v0.6
```

```bash
bash linux/00-preflight-vps.sh
```

重点看：

```text

8443
<PANEL_PORT>
40000
```

**如果 443 已被未知服务占用，停止。**

查谁占：

```bash

```

不要直接 kill。

  +-- REALITY 成功，某网站 403
         → 网站风控 / 特殊出口，不等于入口坏

**不要照抄端口，先核对你机器上的规则。**

# 40. 当前历史案例应该记住什么

## 案例 A：入口 IP/线路问题

现象：

```text
服务器服务正常
监听正常
海外可达
大陆方向请求 tcpdump 根本不到
```

结论：

```text
不要重装 Xray
先看 IP/上游/路径
```

## 案例 B：Docker 8080

现象：

```text
docker 0.0.0.0:8080
localhost curl 200
UFW 8080 ALLOW
公网 timeout
tcpdump 能看到 SYN
```

最后根因：

```text
DOCKER-USER
DROP eth0 tcp dpt:8080
```

结论：

```text
UFW 不是 Docker publish 的唯一防火墙层
```

## 案例 C：OpenAI 403

现象：

```text
curl -I chatgpt.com
403
Cf-Mitigated: challenge
```

结论：

```text
不等于 REALITY 入口挂
先看浏览器/App真实功能
再看出口路由
```

## 案例 D：旧 WARP 运行时注入

旧方案：

```text
Xray runtime API
→ 注入 WARP socks outbound + OpenAI rule
→ Xray restart 后丢
→ watchdog 每 2 分钟补
```

v0.2 起、v0.6 继续沿用：

```text
3x-ui persistent Xray template
→ outbound/routing 正式保存
→ 不再需要 watchdog
```
