HANDBOOK / PUBLIC REFERENCE / OVERVIEW

Small systems, clearly documented.

A compact guide to organizing public notes and static information so the next reader can understand what exists, where it lives, and how it is maintained.

This handbook describes public static content only. It exposes no account, control panel, or private service information.

Quick start

Write the purpose first

One paragraph should explain the audience, the scope, and what the document deliberately does not cover.

Keep paths predictable

Use short names, stable sections, and local assets that do not depend on third-party availability.

Publish a maintenance note

Record when the public material was reviewed, without exposing internal infrastructure details.

Suggested structure

public/
├── index.html      # primary reading path
├── assets/         # local presentation files
├── 404.html       # useful dead end
└── robots.txt     # explicit crawler policy

Conventions

ReadableUse semantic headings and sufficient contrast.
PortableAvoid required external fonts, scripts, and trackers.
DurablePrefer static content over fragile runtime dependencies.
PrivateDo not publish credentials, private metrics, or management links.
